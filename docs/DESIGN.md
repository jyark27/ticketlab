# TicketLab 설계와 실행 방법

## 작품의 범위

콘서트와 야구 예매의 순서를 연습하는 브라우저 웹앱이다. 실제 예매처 계정, 주문, 결제 시스템과 연결하지 않는다. 예매처별 색상과 단계 구성을 참고하되 비공개 대기열이나 실제 판매 재고를 재현한 서비스는 아니다.

콘서트는 4개 예매처와 공연장 4곳을 선택할 수 있다. 야구는 잠실·고척과 NOL·티켓링크 화면을 조합하며 최대 4매를 선택한다. 콘서트의 매수 한도는 2매다. 고척의 티켓링크 화면은 조작 연습 조합이다.

## 실행과 검사

온라인 주소는 https://ticketlab-v.pages.dev/ 이다.

로컬에서는 Node.js 22 이상을 설치하고 `소스` 폴더에서 아래 명령을 실행한다.

```sh
npm ci
npm run dev
```

브라우저에서 http://127.0.0.1:5173 에 접속한다. 개발 서버를 종료하려면 실행한 터미널에서 Ctrl+C를 누른다. Windows에서는 같은 폴더의 start-local.cmd로 실행할 수도 있다. index.html 파일을 직접 열어 실행하지 않는다.

```sh
npm test
npm run build
npm run generate:maps
```

첫 명령은 상태 모델과 자료 검사를 실행한다. 두 번째 명령은 TypeScript 검사 후 dist 폴더에 웹 배포 파일을 만든다. 마지막 명령은 공식 야구 배치도의 클릭 영역 JSON을 다시 생성한다. 앱 실행에는 이미 만들어진 JSON을 쓰므로 Python이 필요하지 않다. 영역 자료를 다시 만들 때만 Python 3과 아래 패키지를 설치한다.

```sh
python -m pip install -r scripts/requirements.txt
```

## 예매 상태

React 화면과 예매 상태를 분리했다. simulator.ts의 reducer가 입장, 보안문자, 좌석, 가격, 수령, 결제, 결과 단계를 처리한다. 선택 가능한 매수와 시간 제한을 상태에서 검사해 화면 버튼의 비활성화에만 의존하지 않는다.

이미 선택한 좌석은 가상 판매 대상에서 제외한다. 다른 구역으로 이동해도 선택 목록을 보존한다. 제한 시간이 지난 선택·다음 단계·결제 요청은 결과 화면의 실패로 처리한다. 야구에서는 한 자리만 고립시키는 선택을 검사한다.

NOL 연습의 좌석 선택 제한은 10분이고, 가격 단계부터의 제한은 7분이다. 다른 예매처 연습은 첫 좌석 선택부터 5분을 사용한다. 실제 상품의 운영 정책과는 다를 수 있다.

## 대기와 경쟁

대기 순번은 오픈 클릭 지연과 난이도로 결정한다. 피켓팅 난이도는 초기 500ms까지 `200 + floor(delayMs² / 3)`을 적용한다. 이후에는 증가 폭을 줄이는 곡선으로 상한 150,000에 접근한다. 따라서 300ms 지연은 30,200번, 500ms는 83,533번이다. 실제 서비스에서 수집한 통계가 아니라 빠른 클릭을 연습하기 위한 조정값이다. 대기 시간은 3~28초로 압축한다.

가상 판매는 남은 좌석에 무작위 점수를 부여한 뒤 일부를 선택한다. 앞쪽·인기 등급의 가중치를 높이되 뒤쪽 좌석도 판매될 수 있게 한다. 초기 재고는 시드가 있는 난수로 분산한다. 같은 시드의 재현이 가능하고 시도마다 다른 재고를 만들 수 있다. 정규시즌보다 포스트시즌의 소진량을 높였다.

## 구역도와 좌석

공연장 구역도는 SVG로 구성한다. 야구는 LG트윈스와 키움히어로즈의 공식 배치도 위에 SVG 클릭 영역을 겹친다. Python 도구는 이미지의 좌석 색상과 번호 위치를 기준으로 블록을 찾고 외곽 다각형을 만든다. 숫자나 통로 때문에 갈라지거나 붙은 부분은 별도로 처리한다. 원본 배치도 이미지는 수정하지 않는다.

잠실의 105개와 고척의 159개는 각각 지도 위 클릭 영역의 개수다. 각 번호 영역은 같은 등급·방향의 11개 연습 재고 그룹으로 연결된다. 블록마다 실제 좌석 재고를 독립적으로 재현한 것은 아니다. 앱에서도 그룹화 안내를 표시한다. SVG 다각형은 마우스 호버·클릭과 Enter·Space 키보드 선택에 함께 사용한다.

고척의 등급별 좌석 사진과 잠실 전경을 펼쳐 볼 수 있다. 사진은 참고 자료이며 선택한 열·번호의 정확한 시야를 나타내지 않는다. 원문 링크와 출처를 화면에 표시한다.

## 결과와 기록

전체 과정은 오픈 반응, 최초 대기 순번, 첫 좌석 선택, 전체 시간을 측정한다. 좌석 집중은 오픈과 대기를 생략하므로 반응속도를 평가하지 않는다. 보안문자는 5회 별도 연습으로 평균 입력 시간과 오입력을 확인할 수 있다.

결과 조언은 모드, 난이도, 성공 여부, 보안문자 오입력, 좌석 선택 실패를 구분한다. 정밀한 개인별 학습 분석이나 실전 성공 확률을 계산하는 기능은 아니다. 예매 기록은 현재 브라우저의 localStorage에 최대 100회 보관하며 서버로 보내지 않는다.

자동 검사는 상태 전이, 재고와 ID, 타이머 경계, 선택 보호, 야구 선택 제한, 경로 분리, 기록 파싱, 지도 영역, 결과 조언을 대상으로 한다. 실제 티켓팅 성공률 향상이나 모든 기기의 성능을 보증하는 검사는 아니다.

## 제작 과정과 도구

평소 티켓팅을 자주 시도했지만 실패하는 경우가 많아, 순서와 좌석 선택을 반복 연습할 공간이 있으면 좋겠다는 생각에서 출발했다. 박지용은 개발과 공동 기획, 오하음은 디자인과 공동 기획을 맡았다. 색상과 UI 배치에 대해 서로 피드백을 주고받았다. 야구장 블록별 호버 영역을 맞추는 데 어려움이 있었고 직접 수정했다.

개발 과정에서 ChatGPT·Codex의 코드 및 문서 작성 지원, 코드 정리, 검사와 영상 편집 지원을 활용했다. 팀은 색상과 UI 배치에 대해 의견을 주고받았고 야구장 호버 영역을 직접 수정했다. 기능은 자동 검사와 실제 조작 시연으로 확인했다. 실전 티켓팅 성공률이 높아지는지는 별도 사용자 실험을 하지 않았다.
